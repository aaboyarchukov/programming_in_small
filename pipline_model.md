# Пайплайны

Ограничения:

- Более крупная проблема декомпозируется с помощью абстракции функций. Функции принимают входные данные и возвращают выходные данных.

- Между функциями не поддерживается общее/глобальное состояние.

- Большая задача решается путем компоновки функций одна за другой, в конвейере, как точное воспроизведение математической композиции функций f ◦ g.

Данный метод характеризуется поэтапным изменением данный и их последующую передачу в следующий входной канал из текущего выходного.
В качестве аргументов, могут быть не только какие-то типы, но и функции, они же могут быть и выходными данными. Такие функции называют - [[Функции высшего порядка]].

Как результат работы данной модели - является объединение независимых функций и их отношения, отсюда вытекает удобство тестирования, а также параллелизма такой программы, так как функция является независимой единицей в системе.

Данный стиль оперирует именно "чистыми" функциями, функции, которые не влияют на состояния мира вокруг, они влияют только на то, что внутри них.

## Пайплайны с продолжением

Продолжение концепции с пайплайнами , только мы к аргументами добавляем - функцию, которая выполняется в конце текущей функции и ее входными данными являются данными, которые будут выходными для текущей функции

> В этом стиле функции принимают один дополнительный параметр -- функцию, которая
> должна быть вызвана в самом конце, и ей передается то, что обычно становится
> возвращаемым значением текущей функции. Это организовано так, что функции не
> возвращаются к вызывающему их коду, а переходят к вызову другой функции.

```go
func f1(...args1, fn_in(...args2) someArgs) someArgs {
	// processing
	return fn_in(outData)
}
```

Такой стиль называется **continuation-passing style** (CPS) - часто используется с анонимными функциями в качестве продолжения, а не с явно именоваными функциями.

Такой стиль дает массу преимуществ:

- [[Элиминация хвостовой рекурсии|элиминация хвостовых вызовов]]
- обработка ошибочных и успешных случаев (например передавать несколько функций, которые запускаешь при возникновении одного из случаев)
- блокировка IO операций, например, при возникновении блокировки - передавать управление в другую функцию
